Sources

Six sources, read every night

Only sources that can be read with no manual steps. Each has its own reader, so if one fails the other five still run.

Local files

1 item = 1 file

Folders you choose. A file holding many notes is still one item.

Notion

1 item = 1 page or subpage

Only the pages you pick. Subpages become their own items.

Gmail

1 item = 1 whole thread

Replies stay together. Promotions and Social are skipped.

GitHub

1 item = 1 commit, PR or issue

Scoped to chosen repositories or a date range.

Google Calendar

1 item = 1 event

Repeating events collapse into one. Events with no description are skipped.

Browser history

1 item = 1 URL

Title and address only, for pages visited at least twice. Searchable, never linked.

Left out on purpose: YouTube history (no API), Kaggle (manual data request), Slack (admin-gated API), Kindle (no API).

Every night at 11 PM

Seven steps turn raw data into a graph

One scheduled batch instead of a live stream keeps the system simple and the model bill small. Answers can be up to a day old.

Nightly run0 23 * * *
  1. 1Extractanything new since last nightextractors/
  2. 2Filterscraps under 20 charactersfilters.py
  3. 3Tagproject and topic, 10 items per model callmetadata.py
  4. 4Savefull text into SQLitesqlite_store.py
  5. 5Chunkabout 400 words, 40 overlappingchunking.py
  6. 6Embedone vector per chunk, into Chromaembeddings.py
  7. 7Linkrelated items, into Neo4jrelationships.py

Linking items

Cheap math narrows it down, a model confirms

Asking a model about every possible pair would be far too slow and costly. Vector distance picks a few candidates first, and only those reach the judge.

10

nearest items from the same project

≤ 0.6

vector distance, or the candidate is dropped

Judge

a model told to say no unless it's sure

≥ 0.6

confidence needed to keep the link

Every link gets a label: implements, discussed_in, planned_in or companion_to.

Storage

Three local stores, one job each

Everything stays on your disk, and all three point back to the same item. Here's where one 3-chunk document, item #482, ends up.

SQLite

Full text of every item and chunk, with a keyword index. Supplies the text an answer quotes.

4 rows

1 item + 3 chunks

Chroma

One vector per chunk, tagged with its project, source and item id. Used to search by meaning.

3 vectors

one per chunk

Neo4j

One node per item once it has a link, plus labelled edges. Used to follow connections.

1 node

chunks never become nodes

Try it

Every question picks its own searches

Plain rules decide, not a model. Keyword search always runs. Meaning search sits out for a "quoted phrase" or a "from someone" filter. Graph search joins when you ask how things connect, starting from the top results of the other two.

These are the same rules as agent/router.py.

Merging results

Ranks are combined, scores ignored

Meaning and keyword scores sit on different scales, so they can't simply be added. Reciprocal Rank Fusion only looks at where each item ranks, so an item that does well in both lists wins. The 60 comes from the original paper (Cormack et al., 2009).

Keyword search

Models

Fully local, or fully cloud

Every model call goes through one provider interface, so the rest of the system never knows which model is answering. You pick the mode in Settings.

Local, with Ollama

Switching modes wipes the ingested data. The two embedding models make vectors that can't be compared, so everything is read in again.

Run it

Three commands, then set up in the browser

Docker Compose starts everything in the right order. Open localhost:3000 and connect your sources under Settings → Guided setup, with no config files to edit.

Give it about 30 seconds. The backend waits until Neo4j passes its health check.

git clone https://github.com/shivamshinde123/personal-knowledge-graph-agent.git
cp .env.docker.example .env && cp config/.env.example config/.env

Evaluation

Measured with LangSmith, not by feel

A fixed set of 26 questions runs through the real agent. Change one setting, run it again, and compare the two runs side by side.

Recall@k

Did the right items come back? Checked by plain code against the items each question expects.

Faithfulness

Is every claim in the answer backed by a retrieved source? Checked by a model judge.

Relevance

Does the answer address the question that was asked? Checked by a model judge.

20 factual, 4 cross-document and 2 synthesis questions. Run with uv run python -m eval.run_evaluation.
