01 · Sources

Six extractors. One graph.

Each source has its own extractor and its own schedule, so one failing never blocks the rest. Items are embedded, indexed for keywords, and linked to each other. A relationship is only stored after an LLM confirms it.

  • Local filesa folder you choose
  • Notionpages + databases
  • Gmailpromotions skipped
  • GitHubrepos, commits, PRs
  • Google Calendarevents
  • Browser historya copied history file

02 · The agent

Routed per question. Merged by rank.

  1. Condense

    Follow-ups are rewritten into a standalone question using the chat so far.

  2. Route

    A rule-based router picks the search paths: quoted phrases skip semantic search, "related to" adds graph traversal.

  3. Retrieve

    Vector search, keyword search and graph traversal over Neo4j each return their best matches.

  4. Fuse & answer

    Reciprocal Rank Fusion merges the lists. The answer cites each item, shown as source chips.

03 · Run it

Four commands to your own graph.

Docker Compose starts Neo4j, the API, the scheduler and the web app. Every value has a working default. Then open Settings → Guided setup to connect sources and Google OAuth from the browser.

Add --profile local-llm to also start Ollama and keep every model call on your machine.

# clone
git clone https://github.com/shivamshinde123/personal-knowledge-graph-agent.git
cd personal-knowledge-graph-agent

# defaults work as-is
cp .env.docker.example .env
cp config/.env.example config/.env

# start everything
docker compose up -d --build

# app → http://localhost:3000
# api → http://localhost:8080/api
